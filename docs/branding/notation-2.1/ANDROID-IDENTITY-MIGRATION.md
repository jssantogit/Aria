Production package/signing, installation alongside an existing legacy app, actual backup restore, visual appearance and in-app icon selection, physical audio, and device-specific rendering remain separate acceptance checks. Do not uninstall the legacy app or move existing files to perform these checks.

Backup validation requires explicit application/schema identity and both content sections, rejects invalid or duplicate months and unsupported listening bucket versions before writing, and retains both supported app tags. Empty but explicitly valid backups remain supported. Decode compatibility is not a transactional guarantee across the independent settings and listening stores; physical restore and disk-failure behavior remain separate concerns.

The matching instrumentation APK is assembled once in the native job and installed alongside the exact application APK. Synthetic legacy import, protected-key preservation, Aria re-export and refusal of incomplete input are tested through the actual Android ContentResolver and application stores. The test is guarded by an explicit runner argument, debug application ID and emulator hardware. This is not permission to restore or replace a user's real data. The shell must not change individual application components; API 34/36 rejected that operation, so the test invokes the app-owned API instead.
